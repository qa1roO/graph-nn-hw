# Локальный запуск на Windows

## Исправление сбоя BGE-M3 (NaN)

На полном документе Ollama 0.23.1 возвращала HTTP 500 / NaN для конкретного
описания ФЕРРОСПЛАВ при обработке BGE-M3 на GPU. Тот же текст на CPU даёт
корректный вектор. Поэтому ноутбук теперь использует bge-m3-cpu:latest
для эмбеддингов, а Qwen по-прежнему работает на GPU. Весов второй модели
скачивать не нужно:

```powershell
ollama create bge-m3-cpu -f Modelfile.bge-m3-cpu
```

Если граф сохранился, повторять извлечение не нужно:

```powershell
uv run python resume_embeddings.py local_runs/vanadiy_review-full-0fea01adef45 --embedding-model bge-m3-cpu:latest
```

Скрипт запускает только эмбеддинги, проверяет неизменность таблиц графа,
сохраняет исходную статистику и отдельный отчёт восстановления в recovery.
После успеха выполните последнюю ячейку упаковки для этой папки запуска
или откройте `hw2/graph-viewer.ipynb`. Строка Pipeline complete сама по себе
не означает успех: GraphRAG печатает её и после Pipeline error.

## Текущий режим запуска

В `hw2/graphtheory-hw2-local.ipynb` установлено `SMOKE_TEST = False`:
первый документ (`vanadiy_review.md`) обрабатывается полностью.
`GENERATE_COMMUNITY_REPORTS = False` отключает генерацию текстовых отчётов
по сообществам и эмбеддингов этих отчётов. Построение графа, выделение сообществ,
эмбеддинги сущностей и фрагментов текста сохраняются. Для возврата отчётов
установите этот флаг в True. Режим входит в отпечаток папки запуска;
старые результаты сохраняются. Глобальный поиск по отчётам без них недоступен.
Полный расчёт запускается пользователем; проверка конфигурации его не запускает.

## Извлечение металлургических знаний (v2)

В локальном ноутбуке подключены `prompts/extract_metallurgy.txt` и
`prompts/summarize_metallurgy.txt`. Они требуют подтверждённых отношений с цитатами,
условиями и отрицаниями; люди и организации исключены из целевых типов.
Добавлен тип СОЕДИНЕНИЕ, чтобы карбид ниобия не путался с элементом или микроструктурой.
Инструкции сохраняются в папку каждого запуска и входят в отпечаток конфигурации:
новый запуск не перезаписывает старые результаты. Новые инструкции применяются
только при повторной индексации; рекомендуем сначала SMOKE_TEST=True.

После индексации `graph_quality.py` создаёт `output/normalized`:
- нормализованные узлы, связи и GraphML для просмотра;
- normalization_audit.csv — названия до/после, изменения типов и пометки;
- quality_report.json — счётчики проблем;
- relationship_review.json — отношения, точные цитаты, связанные исходные фрагменты;
- manual_review.csv — первые 20 отношений для ручной проверки (существующий файл не перезаписывается).

Нормализация объединяет пробелы/подчёркивания и небольшой явный словарь обозначений.
Ошибки OCR не исправляются догадкой. Совпадение цитаты проверяется автоматически,
но это не проверка правильности смысла: заполните manual_verdict и manual_note вручную.
Проверяйте отрицания, условия, направление влияния и отсутствие добавленных фактов.
Исходные таблицы GraphRAG, сообщества и эмбеддинги не меняются; нормализованный
вариант служит для просмотра и проверки, а не заменяет поисковый индекс.

В просмотре можно скрыть изолированные и помеченные узлы, выделить соседей,
показать краткие подписи связей выбранного узла. Полное описание доступно по щелчку.

## Просмотр готового графа

Откройте отдельный ноутбук `hw2/graph-viewer.ipynb`:

```powershell
uv run jupyter lab hw2/graph-viewer.ipynb
```

Выберите ядро Python (graph-hw) и выполните все ячейки. Ollama не нужна.
Ноутбук выбирает последний рассчитанный граф; RUN_INDEX позволяет выбрать другой.
Доступны поиск, выбор и перетаскивание узлов, масштабирование и описания связей.
Работает также экспорт `local_runs/<запуск>/graph.html`, который можно открыть в браузере.
Просмотр не меняет таблицы графа. Для больших графов можно задать MAX_NODES.

Локальный ноутбук: `hw2/graphtheory-hw2-local.ipynb`. Исходный Kaggle-ноутбук сохранён как `hw2/graphtheory-hw2-kaggle.ipynb`.

Используется отдельный Python 3.12: GraphRAG 3.1.0 требует Python >=3.11,<3.14.
Системный Python 3.14 не заменяется. GraphRAG 3.1.0 и LiteLLM 1.86.2 закреплены;
полный набор версий находится в uv.lock. Версия GraphRAG 3.1.2 требует LiteLLM 1.92.0,
у которой в этом окружении не удалось собрать Windows-пакет.

## Окружение через uv

В PowerShell из папки проекта:

```powershell
$env:UV_CACHE_DIR = Join-Path $PWD '.uv-cache'
$env:UV_PYTHON_INSTALL_DIR = Join-Path $PWD '.uv-python'
uv python install 3.12
uv sync --locked
uv run python -m ipykernel install --prefix .venv --name graph-hw --display-name "Python (graph-hw)"
uv run jupyter lab hw2/graphtheory-hw2-local.ipynb
```

Первые две строки задают локальные каталоги uv; повторяйте их в новом терминале.
Они также обходят обнаруженную ошибку доступа к стандартному каталогу кэша uv.
Активировать .venv вручную не требуется. В Jupyter выберите Python (graph-hw).
В VS Code можно выбрать интерпретатор `.venv/Scripts/python.exe`.

## Ollama и модели

Установите Ollama для Windows: https://ollama.com/download/windows
Либо выполните:

```powershell
winget install --id Ollama.Ollama -e
```

После установки откройте новый PowerShell, запустите приложение Ollama и выполните
из папки проекта:

```powershell
ollama pull qwen3.5:9b
ollama pull bge-m3
ollama create qwen3.5-graph -f Modelfile.qwen3.5
ollama list
```

`qwen3.5-graph` — локальное имя той же модели с контекстом 8192 токена;
команда create не обучает её заново. Если приложение не запустило сервер,
в отдельном терминале выполните `ollama serve`. Не запускайте второй сервер,
если порт 11434 уже занят работающей Ollama.

Необязательная исходная модель для сравнения:

```powershell
ollama pull qwen2.5:7b
```

Для её использования задайте в ноутбуке CHAT_MODEL = "qwen2.5:7b".
Параметры контекста этой модели нужно задавать отдельно; Modelfile.qwen3.5 относится к Qwen 3.5.

## Порядок работы

1. Запустите Ollama и установите обе модели.
2. Откройте локальный ноутбук через uv и выполняйте ячейки сверху вниз.
3. Для пробного запуска задайте SMOKE_TEST = True: первые 6000 символов первого документа.
4. Для полного запуска оставьте SMOKE_TEST = False (текущее значение по умолчанию).
5. Для обоих документов задайте DOCUMENTS = ["vanadiy_review.md", "ganoshenko.md"].
   На каждый документ получится отдельный граф.

Сначала ноутбук проверяет модели короткими запросами. Генерация использует
нативный адаптер Ollama через LiteLLM, чтобы отключить thinking параметром
reasoning_effort="none". Эмбеддинги bge-m3 вызываются через локальный /v1.
Одновременно выполняется один запрос. Размерность векторного хранилища — 1024.

Base64 изображений удаляется только из рабочих копий Markdown. Содержимое самих
картинок не анализируется. Сохраняются исходные файлы, подписи и текст.

Результаты: local_runs/<документ>-<sample|full>-<отпечаток>/output/artifacts.
Там находятся entities.parquet, relationships.parquet и другие таблицы; включён
экспорт GraphML. В конце создаётся ZIP рядом с папкой запуска. Он содержит output,
настройки и журналы; кэш в архив не включается. Визуализация в ноутбук пока не добавлена.

Повторный запуск не удаляет кэш. При изменении модели, текста или основных настроек
используется другая папка. Если обновили веса под прежним именем модели, измените RUN_TAG.
Старые результаты остаются на диске. Прерывание ячейки останавливает её дочерний процесс.

## Проверка подготовки

Пакеты установлены; структура ноутбука, синтаксис его ячеек и загрузка конфигурации
проверяются без расчёта графа. Полная проверка ответов моделей и индексации требует
установленной и работающей Ollama. На первом запуске возможна загрузка словаря токенизации.


### Извлечение metallurgy-v3

Промпты уточняют соответствия AlN/NbC/NbN/VC/VN, запрещают числовые значения как узлы и требуют непрерывные дословные цитаты с обоими объектами связи. Суммаризация сохраняет условия без выдумывания противоречий. Проверки отмечают известные испорченные названия и числовые узлы; это эвристики, а не полная проверка истинности. Нормализация применяется к производным данным для просмотра, исходный индекс GraphRAG она не исправляет.

Перезапустите ядро и выполните локальный ноутбук сверху вниз. Новые промпты создают отдельную папку запуска; прежний результат сохранится. Для сравнения сначала используйте тот же первый документ целиком. Qwen остаётся на GPU, BGE-M3 — на CPU, отчёты по сообществам отключены. Изменение качества требует проверки нового результата, оно не гарантировано одним изменением промпта.
