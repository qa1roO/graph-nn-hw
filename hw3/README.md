# HW3: два графа по двум учебникам

Один ноутбук [`HW3_pipeline.ipynb`](HW3_pipeline.ipynb) строит **два общих графа** по учебникам Ганошенко и обзору по ванадию/ниобию. Первый использует Markdown после MinerU без дополнительной предобработки. Второй применяет предобработку к каждому из тех же двух Markdown-файлов, затем строит один граф на объединённом корпусе. Модели, промпты, типы сущностей и остальные настройки GraphRAG совпадают.

## Файлы

| Путь | Содержимое |
|---|---|
| `input/ganoshenko.md`, `input/vanadiy_review.md` | Точные текстовые входы для обоих вариантов. PDF уже обработаны MinerU. |
| `HW3_pipeline.ipynb` | Весь сценарий: подготовка, два запуска GraphRAG, метрики, визуализация, сохранение. |
| `settings.template.yaml` | Одна конфигурация GraphRAG для обоих вариантов; пути подставляются автоматически. |
| `retrieval_probes.json` | 14 контрольных вопросов: по 7 на учебник. |
| `../prompts/`, `../graph_quality.py`, `../Modelfile.*` | Промпты, нормализация графа, определения моделей Ollama. |
| `../pyproject.toml`, `../uv.lock` | Зависимости и зафиксированные версии. |
| `graphs/` | После полного запуска: `before.graphml`, `after.graphml`, `before.html`, `after.html`. |
| `metrics.json` | После полного запуска: все численные результаты, сведения об источниках и версиях моделей. |

`local_runs/` хранит кэш, блоки, таблицы и векторы для возобновления запуска; он исключён из Git. Для воспроизведения из чистого клона он не требуется. После полного запуска добавьте обновлённые `graphs/*`, `metrics.json` и сохранённый вывод ноутбука в коммит, чтобы коллега получил сами результаты.

## Запуск

Нужны Python 3.12, `uv` и работающая Ollama с моделями `qwen3.5-graph:latest` и `bge-m3-cpu:latest`. Из корня проекта в PowerShell:

```powershell
$env:UV_CACHE_DIR = ".uv-cache"
uv sync --locked
ollama create qwen3.5-graph -f Modelfile.qwen3.5
ollama create bge-m3-cpu -f Modelfile.bge-m3-cpu
uv run jupyter lab hw3/HW3_pipeline.ipynb
```

Если модели уже созданы по этим Modelfile, повторное создание не требуется. Выберите ядро из `.venv` и выполните **все ячейки сверху вниз**. Последняя ячейка строит оба графа и считает метрики. Долгую индексацию здесь не запускали; запуск остаётся за владельцем компьютера. При повторном выполнении завершённый индекс используется снова, а незавершённый можно продолжить из кэша.

## Этапы и инструменты

1. **Вход.** Оба Markdown получены через MinerU. Для Ганошенко взята та же текстовая версия, что и в прежнем опыте: встроенные изображения заменены метками пропуска. Контрольные суммы источников фиксируются в отчёте.
2. **Защита и деление.** HTML-таблицы, LaTeX-формулы, числовые величины с единицами и марки стали защищаются. `razdel` делит прозу по предложениям, `tiktoken` считает длину блоков. Цель — 750 токенов, предел — 1024, но крупные таблицы сохраняются целиком и отмечаются для проверки.
3. **Очистка и нормализация.** Удаляются известные артефакты MinerU и лишние пробелы, применяется Unicode NFC. `Pint` проверяет единицы; `pymorphy3` записывает леммы в метаданные токенов, сохраняя основной текст. Подозрительные места помечаются для сверки.
4. **Токенизация.** `razdel` создаёт токены и их символьные координаты; защищённые объекты остаются неделимыми. Готовые блоки после предобработки подаются в GraphRAG вместо его штатного разбиения.
5. **Два графа.** GraphRAG 3.1.0 извлекает сущности и отношения с `qwen3.5-graph`; `bge-m3-cpu` строит векторы описаний сущностей и блоков. Исходный вариант использует штатное разбиение 600/120. В обоих индексах лежат **оба** документа.
6. **Сравнение.** `graph_quality.py` нормализует имена сущностей и сохраняет GraphML. `pyvis` создаёт интерактивные HTML-графы. Ноутбук считает метрики и сохраняет JSON.

Генерация ответа по графу и дообучение моделей не выполняются. Контрольные вопросы используются для проверки поиска и выборочной проверки фактов.

## Метрики

- **Предобработка каждого учебника и суммарно:** число и размер блоков, разбитые абзацы, целостность формул и таблиц, сохранность чисел, число токенов и корректность координат, счётчики очистки, нормализации и проверки единиц.
- **Каждый общий граф:** число сырых и нормализованных вершин и связей, типы сущностей и связей, компоненты, мосты, циклы, изолированные вершины, подозрительные вершины; покрытие блоков сущностями и отношениями отдельно по учебникам; вершины и связи с опорой на оба документа; целостность формул и таблиц в блоках GraphRAG; доля точных цитат и число ответов модели, обрезанных лимитом.
- **Векторизация и поиск:** количество, размерность и корректность векторов; средняя косинусная близость соседних и случайных блоков; Hit@10, MRR@10 и NDCG@10 по 14 вопросам, также отдельно по учебникам.
- **Сравнение:** Jaccard для множеств вершин и связей; выборочная модельная оценка фактов с подробностями в JSON. Она не заменяет ручную проверку.

CER/WER и BERTScore требуют сверенного эталонного текста из исходных PDF, выровненного с Markdown. Точность и полнота сущностей и связей требуют ручной разметки. PDF сам по себе не является готовым эталоном для символьного сравнения. Эти метрики сейчас не вычисляются. Порог 75% можно применять только к метрике, для которой преподаватель определил эталон и способ расчёта. Рост числа вершин или связей сам по себе не означает улучшения качества.

## Проверено до долгого запуска

Оба варианта загрузили по два документа и подготовили блоки: до предобработки 139+14, после — 111+10. Все 14 контрольных цитат найдены в соответствующих источниках и блоках. Предобработка сохранила 222 формулы, 11 HTML-таблиц и 3064 числовые записи; проверка не обнаружила потерь или добавлений чисел. Полная индексация, графовые метрики и поиск будут проверены после запуска последней ячейки.
